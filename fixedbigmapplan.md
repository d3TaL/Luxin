# FixedBigMapPlan — стабильный трекинг большой карты с маркерами

## Проблема

При малейшем сдвиге большой карты сбивается опора (анкор) и запускается полный пересбор SIFT по всем эталонам. Причина: старая сессия уничтожала анкор при первом же `movement_px > 0.6` + appearance failure (`dense_change`/`tile_change`/`controls_change`). Следящий ORB не справляется со сдвигом карты + изменением иконок/облаков/панели, сессия сбрасывается, и каждый кадр ищет заново. Эталонов мало (пара локаций), поэтому после сдвига за пределы покрытия follow не восстанавливается.

Дополнительно отсутствует:
- рендер маркеров grande карты на оверлее;
- фильтрация маркеров по'espace и этажу;
- определение этажа grande карты (сетка не должна меняться при переключении этажа);
- загрузка всех чанков Kongying (сейчас 2 из 46).

## Основное решение: метки показываются всегда

При движении/масштабировании карты метки **не скрываются** — они двигаются вместе с картой через follow-трансформацию. Геометрия публикуется всегда, когда есть последняя известная матрица, даже в фазе `moving`. Точность может быть приближённой во время быстрого движения, но метки не исчезают.

## Инварианты (упрощённые, рабочие)

**C1 (оставить):** Пространство ≠ Этаж ≠ Игрок. `registerBigMap` даёт `space` + матрицу `T_K_to_F`. Этаж определяется отдельно по колонке кнопок. Центр grande карты ≠ игрок. Без этого метки разных регионов смешиваются.

**C2 (упростить):** Матрица `T_K_to_F` может публиковаться для позиции игрока даже когда этаж неизвестен; предметные метки этажа скрываются до подтверждения этажа. Диагностическая геометрия доступна независимо от статуса этажа.

**C3 (упростить):** Много inliers / малый residual / малое изменение пикселей не являются доказательством этажа или пространства, но и не требуют перебора всех эталонов на каждом кадре. Полная перепроверка эталонов (`registerBigMap`) запускается только при сбросе анкора, уходе за экран, истечении срока опоры (>10 с) или ручной смене региона.

**C4 (упростить):** При неопределённом внешнем виде геометрия не удаляется сразу — last known matrix продолжает использоваться для follow. Метки скрываются только при полном сбросе анкора (MAX_NOT_OK подряд).

**C5 (оставить):** Не обновлять timestamp старого кадра, не скрывать конкурентов без причины, не цеплять drifting-преобразования без валидации.

**C6 (упростить):** Первая версия может быть рабочей с флагом `markers_allowed`. Матрица доступна для оверлея после прохождения follow-гейтов. Отдельный renderer с подтверждённым `space`/`layer` — последующий этап.

## Этапы реализации

### Этап 1 — Данные: все чанки маркеров + индекс по'espace/этажу (выполнено)

Загружаются все 46 чанков маркеров Kongying (не только `firstOrNull` + `lastOrNull`). `KongyingMarkerStore` с индексом `space → список маркеров`. `replaceAll` / `upsert` / `markersForSpace`.

Файлы: `app/.../data/KongyingMarkerStore.kt` (новый), `app/.../data/KongyingSyncManager.kt` (изменён).

### Этап 2 — Стабильная сессия grande карты (выполнено, метки не скрываются при движении)

`BigMapSession` с фиксированным абсолютным якорем `anchor_` (кадр `registerBigMap`, не передвигается). Опубликованная матрица `geometry_anchor_` не перезаписывается follow'ом.
- При успехе follow против якоря: матрица компонуется `geometry_anchor_ ∘ motion`, публикуется и сохраняется как `lastPublishedGeometry`.
- При неудаче follow: якорь не уничтожается сразу. Только после `MAX_NOT_OK = 3` подряд — полный `reset()` и абсолютный пересбор.
- При `movement > 0.6` + appearance failure: фаза `moving`, но **геометрия публикуется** (последняя известная матрица), метки остаются на экране и двигаются с картой.
- При смене этажа: не сбрасывать сессию, только перефильтровать маркеры.

Файлы: `tracker/include/luxin/bigmap_session.hpp`, `tracker/src/bigmap_session.cpp`, `tracker/tests/test_bigmap_session.cpp` (новые stage-2 тесты), `tracker/tests/archive/test_bigmap_session.cpp` (старые).

### Этап 3 — Определение этажа grande карты (не меняет сетку)

Детектор колонки кнопок уровней справа: какая кнопка подсвечена (поверхность / уровень 1–3). Группа уровней по центру экрана. Перепроверка ярким фрагментом уровня через изображение уровня Kongying. Выход: `LayerDecision { layerId | surface | unknown }`. Unknown ≠ поверхность. При смене этажа не сбрасывать `BigMapSession`.

Файл: `app/.../tracker/BigMapLayerDetector.kt` (новый)

### Этап 4 — Фильтрация и подготовка маркеров grande карты

Фильтр: `marker.space == geometry.space`; этаж маркера совпадает с этажом grande карты (пустой уровень = поверхность); пользовательские настройки; маркер внутри кадра после проекции `toDisplay`. Кэш проекций — пересчитать только при смене матрицы или этажа.

Файл: `app/.../tracker/BigMapMarkerFilter.kt` (новый)

### Этап 5 — Отрисовка маркеров grande карты на Overlay (выполнено)

Полноэкранный слой `WindowManager` + `View` с `Canvas`. Проекция через `BigMapGeometry.toDisplay` → экранные px → Canvas dp. Иконки по `iconId` с асинхронной загрузкой. Маркеры показываются всегда, когда есть геометрия (включая фазу `moving`). При смене этажа — перерисовка того же Canvas с другим набором маркеров (сетка не меняется).

Файлы: `OverlayService.kt`, `BigMapMarkerOverlay.kt` (новый)

### Этап 6 — Связка в CaptureService (выполнено)

В фазе `tracking`/`moving`/`confirming` публиковать `bigMapGeometry`; при `moving` не очищать геометрию (метки остаются); при `rejected`/`ambiguous` — полный поиск через ≥ 2 с; при смене этажа не сбрасывать `BigMapSession`; при `Stop`/паузе/закрытии — `resetBigMap()`.

Файл: `CaptureService.kt`

### Этап 7 — Проверка

Десктоп: `ctest` (`test_bigmap_geometry`, `test_bigmap_session`, новые stage-2 тесты). Android только через CI (`./gradlew testDebugUnitTest assembleDebug`). Критерий: метки не исчезают при плавном сдвиге; при смене этажа сетка не пересчитывается; после остановки восстанавливаются без полной перепривязки.

## Приемка всего плана

На поддерживаемых эталонах: маркеры телепортов grande карты накладываются на игровые иконки в разных масштабах, со сдвигом, с открытой/закрытой панелью. При движении карты метки не исчезают, а двигаются вместе с картой через follow. При смене этажа сетка не пересчитывается, меняются только видимые маркеры. После остановки карты метки восстанавливаются без полной перепривязки.
