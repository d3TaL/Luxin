# Первый живой трекер и диагностический HUD

Реализация в ветке `feat/tracker-and-data`. Это следующий этап после APK `c96edd5`:
на установленном c96edd5 ещё нет непрерывного трекинга. Новую версию требуется собрать
в GitHub Actions и проверить на устройстве. Метки предметов не рисуются.

## Поток данных

1. Пользователь выдаёт штатное согласие MediaProjection и выбирает Genshin как одно приложение.
2. `CaptureService` получает актуальный Image из существующего ImageReader. Размер меняется
   существующим callback-ом, новый MediaProjection на каждую итерацию не создаётся.
3. Один фоновый обработчик работает с целевой частотой 2 кадра/с. Очередь PNG/Bitmap не копится:
   берётся `acquireLatestImage`, старые/повторные timestamp не обрабатываются. PNG автоматически
   не сохраняются. Ручные снимки остаются отдельной диагностикой и временно приостанавливают трекер.
4. Поддержан полноэкранный альбомный Genshin с равномерным уменьшением кадра. Калибровка
   масштабируется с короткой стороны дисплея в высоту альбомного bitmap. Проверка aspect ratio
   не является универсальным определителем crop/insets; оконный режим пока не проверен.
5. Дешёвая проверка цвета стрелки игрока защищает от обработки меню/большой карты/экрана запуска.
   Отсутствие стрелки, скрытое приложение, устаревший кадр или смена размеров очищают состояние
   вывода и сбрасывают привязку. При возвращении нужен новый подтверждённый захват.
6. `NativeSplitTracker` владеет загруженными эталонами на протяжении сеанса. На кадр вызывается
   `updateFrameJson` с Image.timestamp и откалиброванным кольцом в пикселях bitmap.
7. Типизированный декодер не превращает native error в координаты (0,0) и не сохраняет старый
   этаж при pending/unknown. Поверхностный position_only набор намеренно не определяет этаж.
8. HUD и Activity читают один StateFlow: набор, режим поиска/позиции, координаты, масштаб,
   этаж, inliers, длительность C++, фактическую частоту обработки и возраст кадра.
   Эти величины не являются измерением полной задержки до визуально совмещённых меток.
9. Остановка/системное завершение MediaProjection отменяет обработчик, закрывает native handle
   в его finally и очищает HUD. Epoch на Main не допускает позднего результата после Stop.

C++ пороги и алгоритм классификации не менялись ради этого подключения. На первом этапе
использовать режим одного приложения: исключение кольца/HUD подтверждено в ручном тесте.
Полный захват с нарисованным тестовым кругом не является проверенным режимом живого трекера.

## Загрузка эталонов

Эталоны не встроены в Git/APK: исходные тайлы и PNG Kongying по-прежнему вне репозитория.
Для спайка используется явный импорт через системный выбор файла (SAF):

- `manifest.json`, `schemaVersion=1`, `id`, `title`, `mode=layered|position_only`;
- 1–8 описаний `layers`: `id`, `name`, `space`, `image`, `activeMask`, `contextMask`,
  `unitsPerPx`, `originX`, `originY`;
- плоский ZIP с PNG и масками, без абсолютных путей/директорий/дубликатов;
- импорт ограничен по количеству файлов, распакованным байтам и числу пикселей;
- новая версия устанавливается отдельно и активируется только после проверки. Старый набор
  не должен повреждаться при неудачном импорте и не удаляется из-под работающего трекера.

Генератор: `spike/package_references.py`. Подготовлены локальные архивы в
`spike/out/reference-packs/`:

| ZIP | Область | Что проверяем |
|---|---|---|
| `faded-castle-v1.zip` | Обветшалый замок | Позиция + 4 конкурирующих этажа |
| `snowmelt-channel-v1.zip` | Канал отвода снега | Позиция + 3 уровня |
| `mondstadt-v1.zip` | Город Мондштадт | Только позиция, этаж не определяется |

Набор ограничен своей областью. Это не автоматический поиск по всему Тейвату. Вне области
ожидается поиск/отказ; возможные ложные фиксации надо отдельно проверять, не считать HUD GPS.
Новый набор Ли Юэ пока не подготовлен: `assets.yuanshen.site` возвращает TLS unexpected EOF
двумя клиентами, без отключения проверки сертификатов. Оставлены кэш и диагностические логи;
скачивания не заменяются данными другого источника.

```sh
python -I spike/package_references.py <НОВЫЙ_ZIP> --id faded-castle \
    --title 'Обветшалый замок' --mode layered \
    --ref 'Нижний=<prefix_UG3>' --ref 'Средний=<prefix_UG2>' \
    --ref 'Верхний=<prefix_UG1>' --ref 'Зал=<prefix_HALL>'
```

## Проверка следующего APK

1. Импортировать ZIP нужной области в карточке «Живой трекер — диагностика». Набор должен
   сохраниться после перезапуска. Ошибочный/слишком большой ZIP не должен сбрасывать старый.
2. Включить оверлей, запустить захват одного приложения и выбрать Genshin. Открыть область,
   соответствующую набору. Запустить трекер из Activity или кнопкой HUD «Трекер».
3. Убедиться, что HUD получает новые координаты при движении и что кольцо не мигает.
   Сравнить со стрелкой на большой карте вручную, не только с плавностью цифр.
4. Открыть большую карту/меню, свернуть выбранную игру, остановить запись системной кнопкой:
   старые координаты не должны оставаться как действующие. Повторно запустить сеанс.
5. В замке/канале пройти лестницу: координаты продолжаются, этаж в переходе может быть неизвестен.
   В Мондштадте ожидается «этаж не определяется этим набором», не выдуманная поверхность.
6. Проверить быстрые Start/Stop, ручной снимок при трекинге, смену ориентации и калибровки.
7. Записать FPS игры, нагрев и диагностические длительности 5–10 минут. Копирование bitmap
   пока полноразмерное; экономия памяти/обработка ROI — отдельная оптимизация после измерения.

Пока не реализованы автоматическое скачивание/построение CV-индекса всех регионов, карта
в приложении, отметки собранного и вывод предметных меток на игровую карту.
